# Eric 的貼文寫作風格

## 風格核心

科技工作者的思考流——像在跟朋友說「我最近在想一件事」，不是在寫文章，不是在教學，是在分享一個還在形成中的洞見。

帶有不確定感的誠實，比充滿自信的結論更有說服力。

---

## 句法特徵

**開頭用問句帶入，製造懸念**

```
✅ AI 時代，99% 的努力可能真的是白費的？
✅ 這件事值得認真想嗎？
❌ 今天想跟大家分享一個關於 AI 時代的觀察
```

**短段落，一段一個概念，留白讓人呼吸**

每段 1-3 句。段落之間不需要過渡句。讀者自己會跟上。

**用「但」做轉折，不用「然而」「不過話說回來」**

```
✅ 但可能那些「白費」的過程裡...
❌ 然而，若我們換個角度來看...
```

**結尾要有力道，一句話收斂全文**

```
✅ 所以找到自己真的有熱情的方向，然後持續做，打造自己的差異化品牌
✅ 差異化不是設計出來的，是熬出來的
❌ 希望這些想法對你有所啟發！歡迎留言分享你的看法
```

---

## 用字原則

**保留英文技術詞彙，不硬翻**

```
✅ skill、workflow、harness engineering、ETF
❌ 技能、工作流程、測試工程、指數股票型基金
```

**用「可能」「某個時間點」保留思考的模糊感**

這不是不確定，是誠實。強迫給出答案反而失真。

**口語但不俗氣**

「蠻」「其實」「等等」可以用，但不要出現「超級」「根本」「完全」這種網路誇飾語。

---

## 格式規則

- 不用標題（沒有 `##`）
- 不用條列（沒有 `-` 或 `•`）
- 不用粗體強調
- 不用表情符號（除非用戶原文有）
- 段落之間空一行

---

## 內容結構（常見模式）

```
[問句 / 反直覺的觀點]

[具體展開：技術細節、真實情境]

[轉折：但是...]

[洞見：為什麼這樣反而有意義]

[行動建議：一句話，直接]
```

不一定每篇都要五段，但這個思路是：**挑釁 → 具體 → 轉折 → 洞見 → 行動**。
